# app-layout

## Requirements

### Requirement: 精简的顶层导航结构
系统 SHALL 将顶层导航收敛为业务标签：指数行情、严选基金、严选 ETF、严选股票、估值温度、公众号；管理入口（数据源管理、用户管理）靠右排列且按权限显示。导航中 SHALL NOT 存在"PE 分析"和"投资策略"入口。

#### Scenario: 查看顶部导航
- **WHEN** 已登录管理员访问网站
- **THEN** 顶部导航展示：指数行情、严选基金、严选 ETF、严选股票、估值温度、公众号、数据源管理、用户管理，且无 PE 分析和投资策略入口

#### Scenario: 访客查看导航
- **WHEN** 未登录访客访问网站
- **THEN** 导航仅展示业务标签，不展示数据源管理和用户管理入口

### Requirement: 统一的页面骨架
每个标签页 SHALL 采用统一的页面骨架：内容起始区（一行说明或操作区，可选）+ 卡片化内容区，形成"导航 → 内容 → 弹窗"清晰的视觉层级。页面内 MUST NOT 出现与当前导航标签同名的标题（避免重复）；仅含单一内容块的页面不设标题，含多个内容块的页面以小节标题区分。

#### Scenario: 切换标签页
- **WHEN** 用户在指数行情、严选基金、严选 ETF、严选股票、估值温度之间切换
- **THEN** 各页面均直接进入内容区，不显示与导航标签重复的大标题，视觉层次连贯

### Requirement: 统一的弹窗与搜索交互样式
各模块的详情弹窗（指数详情、基金详情、ETF 详情、登录）与搜索框（指数、基金、ETF、股票）SHALL 使用统一的 CSS 类与 DOM 结构模式，视觉表现一致。

#### Scenario: 打开不同模块的搜索框
- **WHEN** 用户分别打开指数搜索、基金搜索、ETF 搜索、股票搜索
- **THEN** 四个搜索框的样式、交互行为与结果下拉展示模式一致

### Requirement: 已删除功能无残留入口
系统中 SHALL NOT 存在指向已删除功能（PE 分析、投资策略及其子模块）的死链接、死按钮或残留 UI 元素；前端代码中 SHALL NOT 存在对 `/api/strategy/*` 与 `/api/position/*` 的任何调用。

#### Scenario: 全站无策略残留
- **WHEN** 用户浏览所有标签页及移动端菜单
- **THEN** 不出现任何投资策略、定投、网格、加仓相关入口或按钮

#### Scenario: 前端无策略 API 调用
- **WHEN** 检查前端代码中的 fetch 调用
- **THEN** 不存在指向 `/api/strategy/*` 或 `/api/position/*` 的请求

### Requirement: 主题体系保持
排版重构 SHALL 保留现有深色/浅色双主题机制（CSS 变量 + `data-theme` 属性），重构后的骨架、卡片、弹窗在两种主题下均正常显示。

#### Scenario: 切换主题
- **WHEN** 用户在重构后的页面上切换深浅主题
- **THEN** 所有页面骨架、卡片、弹窗、搜索框颜色随主题正确切换，无不可读元素

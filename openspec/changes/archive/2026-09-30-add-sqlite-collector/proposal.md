## Why

当前的数据链路是"请求驱动"：用户打开页面时，如果缓存过期，服务端在请求线程里同步去调外部数据源（东财、腾讯、蛋卷、知有行）。实测交易时段 `/api/stocks` 2.7 秒、`/api/etfs` 4.1 秒、无缓存时指数行情 7 秒；而外部源限流时（2026-09-30 东财全天间歇性 `socket hang up`），页面直接受影响。

同时系统没有任何历史沉淀：JSON 缓存只存"最新一份"并整份覆盖写，无法回答"沪深300 过去一年 PE 怎么走的"这类问题；10 年 K 线每次刷新都整份重抓重写（`indices.json` 4.9MB、`active-funds.json` 4MB）。

本变更把数据链路改为"后台采集写库、网站请求只读库"，并建立永久的历史数据：日 K、基金净值、每日估值快照、温度，同时在页面上提供估值与温度走势曲线。首要目标是**稳**：外部源失败时网站照常返回上一份数据，任何单点失败都不影响其他部分。

## What Changes

### 数据存储
- **服务器系统与 Node 版本不变**（CentOS 7.6 + Node 16）。SQLite 驱动选用纯 WASM 的 **sql.js**（生产机实测可用；better-sqlite3 在该系统上无法安装）
- 数据分两个文件，均位于 `data/db/`（与现有部署"不覆盖 `data/`"规则一致）：
  - `latest.json`：最新行情与采集状态，盘中每轮采集后更新
  - `market.db`：历史库——日 K（补齐开盘价、成交量、成交额）、基金每日净值、每日估值快照（**永久保存**）、分位参考线、每日任务日志，一天更新几次
- 两个文件都由采集进程**先写临时文件再改名**，网站永远读到完整文件
- 关注清单**继续使用现有 watchlist 文件**，网站增删逻辑不变；库中维护一份镜像，删除后历史保留，重新添加同一标的时历史自动接续
- 每日自动备份库文件，保留 14 份

### 后台采集
- 新增独立的采集进程（PM2 第二个应用），是行情数据的唯一写入者；网站进程只读行情数据
- **盘中**：指数、股票、ETF 各自独立计时，每次间隔在 **5～10 秒内随机**；失败时逐步拉长间隔（最长 2 分钟），恢复后回到随机区间；A 股午休与各市场休市时不采集；数据连续不变时降频
- **收盘后**：每个交易日保存一份快照（当日 K 线 + 估值 + 温度）；失败时重试，最终仍失败则使用盘中最后一次成功值并标注"兜底"
- **基金**：每天晚上采集一次净值
- **交易日判断**：不维护节假日表，以数据源最新 K 线日期是否变化判断当天是否开市；美股交易日按美东时间归属
- 启动时检查历史缺口并从数据源补齐（K 线、净值、可回补的估值）

### 历史回补（一次性）
- 指数 PE/PB：蛋卷历史接口（约 2016 年起，周线）；港股创新药用中证官网（2021-10 起，日线，仅 PE）
- 股票 PE/PB：东财数据中心个股估值报表（2018 年起，日线）
- K 线：现有数据源补齐开盘价与成交量；创业板50、自由现金流改用国证官网（2010/2012 年起完整日线）
- 温度：无历史接口，从上线当天开始积累

### 页面
- 指数详情弹窗的"区间走势"增加 **PE / PB / 温度** 切换，复用现有 1/3/5/10 年周期按钮
- PE、PB 曲线附带 30 / 50 / 70 分位参考线（来自蛋卷），**不画百分位曲线**；横轴按日期排列（历史周线与近期日线混合）
- 温度曲线起点标注"自 2026-09-30 起记录"
- 股票详情同样提供 PE / PB 曲线；ETF 显示其跟踪指数的估值曲线
- 无估值数据源的标的显示"暂无估值数据"：创业板50、自由现金流、兴全商业模式 LOF（163415）

### 网站读路径
- 所有行情、历史接口改为只读 `latest.json` 与 `market.db`（文件变化时才重新加载），请求线程不再调用外部数据源
- 通过开关在"读库"与"原有逻辑"之间切换，可一键回退

## Capabilities

### New Capabilities
- `sqlite-storage`：数据库结构、单一写入者、原子落盘、幂等主键、关注清单镜像与历史接续、每日备份
- `market-data-collector`：后台采集进程——盘中随机间隔采集、失败退避、交易时段与交易日判断、收盘快照与兜底、基金晚间采集、缺口补齐
- `valuation-history`：估值与温度历史——多数据源回补、单曲线单数据源、来源与粒度标注、无数据源标的的处理
- `valuation-trend-chart`：页面上的 PE / PB / 温度走势曲线与分位参考线

## Impact

- **前置依赖**：无。服务器系统与 Node 版本不变
- **后端**：新增 `services/db/`（sql.js 加载、建表、迁移、原子落盘、只读副本、数据访问）、`collector.js`（采集进程入口）；`server.js` 的行情接口改为读库（开关控制），关注清单接口不变；统一三份交易时段判断（`stockFetcher.js`、`etfFetcher.js`、前端 `isMarketOpen`）为一处
- **前端**：`public/index.html` 指数、股票、ETF 详情弹窗增加估值 / 温度曲线；交易时段轮询间隔与后台节奏对齐
- **新接口**：估值历史、温度历史（按标的与周期查询）
- **进程**：PM2 由 1 个应用变为 2 个（`dale-compass` 网站 + `dale-collector` 采集）
- **依赖**：新增 sql.js（纯 JS + WASM，无原生编译）；发布包带上 `node_modules/sql.js`，服务器上仍不执行 `npm install`
- **内存**：两个进程各持有一份库，预计合计增加 100MB 以内（服务器 2GB），上线前用真实数据实测
- **外部请求**：盘中持续请求量约为每类每小时 480 次（平均 7.5 秒一次），休市时基本为零；首次上线有一次性历史回补请求
- **数据**：一次性导入现有 4 个关注列表与 JSON 缓存中的 K 线、净值；原 JSON 文件保留不删，作为回退依据
- **后续**：稳定运行 1～2 周后，另起变更 `retire-json-cache` 删除旧的请求时采集逻辑与 JSON 缓存

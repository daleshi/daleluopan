## Why

「基金总览」一个页面同时放了两块不相关的内容：上面是上证指数风向标加指数实时行情（高频刷新的市场数据），下面是严选基金（指数基金 / 主动基金的低频跟踪）。页面很长，要看基金得先滚过整块指数区。两块内容在进入页面时一起加载，但交易时段只有指数部分需要轮询刷新。页面名叫"基金总览"，主要内容却是指数行情，名字和内容对不上。拆成两个顶层标签页可以让每一页只讲一件事，也让数据按需加载。

## What Changes

- 把现有 `#tab-dashboard`（基金总览）拆成两个顶层标签页：
  - **指数行情**：沿用 `data-tab="dashboard"` 这个标识（保持默认首页、调度器、登出回跳逻辑不变），包含上证指数"市场风向标"大卡片（`#featuredIndexRow`）和指数实时行情区（搜索、A股/港股/美股 分类 Tab、指数卡片网格、指数详情弹窗入口）
  - **严选基金**：新增 `data-tab="funds"`，包含基金搜索、指数基金 / 主动基金 分类 Tab、基金卡片网格和基金详情弹窗入口
- 导航注册表 `NAV_TABS` 新增"严选基金"条目，原"基金总览"改名为"指数行情"；桌面顶部导航和移动端底部导航 / "更多"面板都由注册表自动生成
- 数据加载按标签页拆开：进入"指数行情"只加载 `loadData` / `loadIndexQuotes`；进入"严选基金"才加载 `loadActiveFundData`（懒加载，首次进入才请求，已加载过就直接用缓存）
- 顶部"刷新数据"按钮（`refreshCurrentTab`）加上 `funds` 分支；交易时段轮询调度器维持只刷新指数行情的现有行为
- 每个页面有自己的 page-header（标题 + 副标题），替换原来那个合在一起的"指数实时行情 · 估值水位 · 严选基金跟踪"副标题
- 后端无改动：`/api/active-funds*`、`/api/indices*` 接口保持不变

## Capabilities

### New Capabilities
- `dashboard-tab-split`：顶层标签页拆分。定义"指数行情"和"严选基金"两个标签页各自包含什么内容、导航入口怎么排、数据什么时候加载、刷新和轮询归属哪个页面、移动端导航怎么同步

### Modified Capabilities
- `index-quotes-panel`：「指数行情面板按市场分类切换」这条需求目前写的是位于「基金总览」页，需要改成「指数行情」页（分类行为本身不变）

## Impact

- **前端**：只改 `public/index.html`
  - HTML：把 `#tab-dashboard` 里的严选基金 section（大约 3558-3600 行）挪到新的 `#tab-funds` 容器里，两边各有自己的 page-header
  - JS：`NAV_TABS` / `NAV_MOBILE_MAIN` 注册表（约 6397-6406）、tab 切换处理（约 6436-6465）、`refreshCurrentTab`（约 4484-4498）、启动流程（约 9886-9890）
  - 基金搜索添加成功后的回调（约 8390）和删除回调（约 7292）不用改：它们操作的 DOM id 不变
- **后端 / API / 数据**：无改动
- **相关变更**：进行中的 `redesign-tabs-and-layout`（第 6 组排版重构、第 7 组移动端导航还没做）也会动导航和页面骨架。本变更只基于它已经完成的 `NAV_TABS` 单一注册表来增加标签，不跟它剩下的视觉重构任务冲突
